How statuses are mapped, and what is counted

Shopify reports more than three dispute statuses. Each one is folded into exactly one of the three used here:

Reported hereShopify status
Openneeds_response, under_review, warning_needs_response, warning_under_review, response_disabled
Wonwon, warning_closed, prevented
Lostlost, accepted, charge_refunded

Prevented cases count as won. Shopify blocks some disputes before any money moves and marks them prevented — no loss, but no defence was mounted either. They are folded into Won so that Total = Open + Won + Lost holds, labelled prevented in the table below, counted separately under the Won figure, and selectable on their own in the Status filter. Filter to Won — defended to see the win rate on cases actually fought.

One case, one row. Rows are keyed on the Shopify dispute ID, so an order with several transactions still counts once. A repeated dispute ID is dropped and reported in the data notes above. Only cases Shopify records as separate disputes appear as separate rows.

Dates. Filtering uses the date the dispute was created (Shopify's initiated_at), in the store's own timezone. Outcome date is the date the case was finalised.

Win rate. Won ÷ (Won + Lost) × 100. Open cases are excluded from the divisor. With no closed cases in range, the rate reads “—”.

Where the data comes from · paste an export

The dashboard reads the JSON or CSV written by chargebacks_export.py, which pulls shopify_payments/disputes.json from all four stores. Expected columns:

dispute_id, store, created_at, created_date, order_number, order_id,
customer, amount, currency, reason, status, status_raw, case_type,
outcome_date, evidence_due_by
